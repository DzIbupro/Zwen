# 技术决策：Rust + Tauri 2

日期：2026-10-29。结论：**正式产品采用 Rust 后端、Tauri 2 桌面壳、TypeScript + Svelte 前端；SQLite 元数据 + Markdown 笔记。**

这是一项针对当前需求与本机证据的工程选择，不是“Rust 天生不会崩溃”或“三种语言性能排名”。优先满足精致面板、正常表格公式、交互知识网络、合理内存和可恢复性。

## 本机对照结果

Fedora 45 / Niri，rustc/cargo 1.98.1，GTK4 4.24.1，两个 WebKitGTK API 均为 2.54.1，Python 3.15 / PyGObject 3.58.1。Rust 候选使用 release 构建；正式轮次没有并行编译或同时运行其他候选。每个候选运行三次，每次约 35 秒。

| 完整架构 | 峰值 PSS 中位数（范围） | 峰值 RSS 合计中位数 | 隐藏阶段 PSS 中位数 |
|---|---:|---:|---:|
| Python + GTK4 + WebKit6 | 392.9 MiB（381.7–399.3） | 670.2 MiB | 348.6 MiB |
| Rust + GTK4 + WebKit6 | 401.2 MiB（374.6–433.2） | 671.5 MiB | 344.3 MiB |
| Rust + Tauri 2 / WebKitGTK4.1 | 367.9 MiB（360.7–414.2） | 615.8 MiB | 339.1 MiB |

统计包含本次应用的全部可追踪子进程，而不是仅主进程。PSS 按比例分摊共享页，RSS 相加会重复计算共享库等页面；GPU 专有内存未完整统计。GTK4 宿主设了 GSK_RENDERER=cairo，WebKit 自身未统一禁用加速；Tauri 使用 GTK3，不使用这个 GSK 选项。这也是架构/配置对照而非纯语言对照的原因。1 MiB = 1,048,576 字节；367.9 MiB 约为 386 MB。

**不能把这张表宣称为“成品已经低于 500 MB”。** 三组范围重叠，WebView 资源占主导；Rust GTK 并未因换语言显著省内存。若以所有进程 RSS 相加作为 500 MB 硬门槛，本轮没有证明达标。保留用户约 500 MB 的体验目标，同时持续报告 PSS/RSS，不能通过换口径隐藏实际占用。

三个样例使用同一离线页面及固定依赖：Marked 18.1.2、DOMPurify 3.4.17、KaTeX 0.19.1、Cytoscape 3.34.4；真实 Markdown 表格、行内/块级公式、代码、1280×720 合成图片、50 节点/约 75 边网络、50 次模拟流式更新。全部九轮内容检查、损坏公式/脚本净化、20 次图谱重建、100 次显隐均完成，进程正常退出。GTK4 在极快显隐时有帧时序警告，未发生异常退出；Tauri 三轮标准错误输出为空。这不是长期可靠性评分。

请求窗口均为 900×850；由 Niri 平铺与缩放分配实际尺寸，并非严格固定像素的实验室基准。Tauri 附加测试记录的实际 CSS 视口为 800×926、DPR 约 2.1；未逐轮核对三个候选的实际几何。因此结果用于判断本机可行性，不用于宣称语言级性能优势。独立的 GTK/WebKit 实际快照已目视核对表格、公式、图片和图谱；这是技术页面，尚未由用户确认最终 Vida 式交互。

## 为什么选择这一组合

1. **完整展示更直接。** CSS 面板、Markdown、公式和图谱可使用同一套网页组件。若选择 GTK 仍需嵌入 WebKit，当前证据没有显示额外的资源收益。
2. **Rust 管理重要状态。** 输入、请求、文件、数据库与整理任务留在 Rust，用类型、边界校验与测试约束状态变化；前端只负责交互和展示。收益是结构与交付，不是免除逻辑错误、系统库和驱动故障。
3. **桌面集成可集中管理。** Tauri 提供窗口、IPC 与打包基础，Linux 使用系统 WebKitGTK；不增加常驻 Node 或本地模型服务。[WebView 官方说明](https://v2.tauri.app/reference/webview-versions/)、[前端配置](https://v2.tauri.app/start/frontend/)。
4. **资源有可用空间，但仍需控制。** 本机短测 PSS 接近 360–414 MiB，符合继续实现和优化的条件。长历史、截图与整理任务必须设置缓存/并发/展示上限，正式版本重新验收。

Svelte + TypeScript 是正式界面的维护性选择，**本轮测量页面是原生 JavaScript，没有测量 Svelte 成品**。不采用 SSR 或 SvelteKit 服务端；构建后只交付静态资源。框架自身及完整业务的增量内存由下一阶段复测。

Python 不作为产品常驻后端；旧代码保留为历史验证。Go、Java 都能实现可靠软件，但未发现值得增加两套原型的特定优势；本轮没有测量它们，不作成熟度或内存高低判断。也不混用 Python/Rust/Java 多个常驻后端。

## 稳定性补测与实际限制

附加测试只向隔离样例自身的一个 WebKit 渲染子进程发送 SIGKILL：Rust 主进程存活，2 秒后主动重载，第二次完成全部内容检查；随后隐藏 60 秒，再显示时公式和图片仍可用，正常退出。隐藏 59 次采样 PSS 从约 315.8 降至 303.6 MiB。**这证明可以实现受控重载，不代表 Tauri 已自动替产品完成恢复。** 正式实现需检测渲染终止、从已持久化状态重建并提示用户。

第一次故障脚本因 Python 文本缓冲与 select 的竞态，延迟到 reload 时才注入故障，未恢复；保留了该次记录。改为字节读取并逐行处理后，信号在 armed 阶段立即注入，2 秒后才 reload，测试通过。它不能算作同条件下的一次框架稳定性失败。

本轮未包含真实 Provider、SQLite、20 张不同截图、超大输入拒绝、断网/异常 SSE、中文输入法、多显示器焦点、30 分钟/8 小时持续使用和数据库/磁盘故障；也没有可靠的热唤出延迟或完整 GPU 统计。60 秒隐藏测试未记录 CPU，三候选的 16 秒窗口不足以完成原计划的 60 秒空闲 CPU 验收。以上仍为发行门槛，不勾选为通过。此前的 Niri 截图验证只证明原型接口链路，不代表 Tauri 新壳已集成验收。

## 确定的产品结构

| 层 | 选择与边界 |
|---|---|
| 桌面 | Tauri 2，单实例；Niri 快捷键调用显式入口，不自动采集当前应用 |
| 前端 | Svelte + TypeScript + CSS；轻面板、历史、材料预览、知识库和图谱 |
| 展示 | Marked + DOMPurify、KaTeX；依赖本地打包，外链由系统浏览器打开 |
| 网络 | Rust 异步任务；Provider、超时、取消、完整 SSE/UTF-8 边界、generation ID |
| 本地状态 | Rust + SQLite（单一受控数据库工作队列）；草稿先保存、迁移前备份 |
| 笔记 | Markdown 正文 + 相对附件；稳定 ID、修订检查、可迁移目录 |
| 自动整理 | Rust 任务队列调用用户接入的 AI；栏目/多归属/关系、证据、撤销和人工保护 |
| 网络可视化 | Cytoscape，按需局部加载、筛选、展开、定位笔记与证据 |

UI 不直接获得任意 shell、文件路径或密钥权限。受信任前端仅调用明确注册且校验参数的业务接口；IPC 权限、内容净化、CSP 均按正式应用配置。测试页含内联脚本，仅供离线技术验证，不能直接作为生产安全模板。

## 后续开发顺序

1. Rust/Tauri + Svelte 正式工程、单实例、最小 IPC、草稿持久化及故障恢复；给用户查看可交互的面板样例，并复测进程树资源。
2. 一个真实 Provider 的流式聊天、停止与历史；完成选区/截图附加到草稿，以及正常表格公式展示。
3. Markdown 知识库、搜索、来源、附件与人工编辑。
4. AI 增量栏目/关系整理、证据、变更集撤销与人工修正保护。
5. 可视化知识网络，随后验证自动划词浮条。

这是选型后的阶段顺序；具体业务任务仍需测试与实施计划。本轮没有把样例包装成可用产品。
