# 产品需求基线 v2

确认日期：2026-10-29。根据仓库所有者在本轮对话中的最终确认修订；本文件是产品范围的依据。工程建议与验收预算不等同于用户指定的数值要求。

## 产品目标与优先级

在 Fedora＋Niri／Wayland、约16GB内存的个人电脑上，提供好看、轻量、稳定的桌面学习助手；把问答材料保存下来，由接入的AI自动组织为可见、可探索的知识网络。

决策优先级：数据可靠与运行稳定 → 合理的资源占用 → 完整核心工作流与良好视觉交互 → 开发便利。不可为了减少内存而交付无法正常阅读的表格／公式，也不可为了外观默认引入持续高负载。

语言由验证决定；用户不熟悉Rust不是排除Rust的理由。用户授权调整技术方案，但没有指定最终语言或框架。

## 前端与交互

- 全局快捷键快速唤出与收起助手，尽量保持阅读连续性。
- 以Vida桌面面板的视觉与交互为参考，形成精致、简洁的输入、材料预览和回答体验。具体面板尺寸、位置、配色、展开和收起动效尚待视觉样例确认；官网观察不等于桌面客户端实测。
- 支持普通聊天、流式回答、停止、连续追问、历史回看和继续对话。
- 选中文字后解释／翻译／自定义提问；原始愿望包含自动划词操作条。先提供选区快捷键，自动浮条仍为后续正式目标，不因Wayland限制被悄悄删除。
- 独立截图快捷键，区域截图直接附加到草稿；可补问题、删除附件、重截、取消，确认发送后才请求模型。
- 首版回答正确展示常用Markdown：段落、标题、列表、引用、代码块、表格，以及行内／块级数学公式。宽表格、长公式和代码可滚动，不能截断关键信息；支持复制。
- 支持中文输入法、键盘操作、实际双屏与100%／150%缩放。

## 输入边界与后端

- 快捷唤出只打开助手，不自动读取／附加当前应用内容，不自动把窗口标题当成文献来源。
- 提问材料由手动输入、显式选区动作、显式复制入口、截图提供。可选自动划词模式只能本地呈现候选材料，不能据此自动上传。
- 远程模型由用户配置；模型必须明确支持所需文字／图片能力。默认不常驻本地大模型、OCR引擎、向量服务。
- 会话上下文支撑追问；超限有明确提示与可查看的范围，不能静默丢弃关键材料。
- 网络、鉴权、限流、格式错误、取消等可恢复失败不导致整个应用退出；保留草稿、附件和已收到的回答。
- 草稿、历史、笔记与附件本地持久化；来源可补标题、URL／文件位置、页码，未知留空。

## AI知识整理与可视化

- 用户选择保存的问答、摘录、笔记和截图进入知识库；默认不把所有聊天无条件上传给整理模型。
- 接入的AI自动识别主题与知识点、归类到栏目，并识别跨栏目关联；一个知识点可属于多个主题。
- 新内容加入后可以自动增量整理；用户首次启用整理时明确模型与数据范围，之后范围内自动运行，无需逐条批准关系。
- 栏目与知识点可以合并、拆分、改名、重新归类；AI整理可回溯、可撤销，人工调整受保护。
- 材料修改后，依赖旧正文的AI分类／关系失效或待重算；材料删除后不能留下可点击的悬空证据，保留人工修正和可撤销记录。
- 分类与关系必须指向知识库中的证据材料；模型推断有独立标记，不将推测展示成已证实事实。
- 可视化网络支持节点与连线、缩放、拖动、搜索、主题筛选；点击节点打开知识，点击关系查看说明与证据。
- 初始展示局部网络，按需展开；大知识库不能一次加载全部节点导致卡顿。
- Markdown文件作为笔记正文的主要存储形式；支持统一位置管理、搜索、来源回看、附件与笔记链接，方便使用其他工具打开。

## 范围边界

不建设论文出版排版系统；不自动采集当前应用上下文；不默认持续录屏；不把Vida的主动推荐和自动操作电脑功能带入本项目。知识图谱与AI自动整理是产品正式目标，按阶段交付，不作为随时可删除的附属实验。

## 稳定性验收原则

不承诺绝对零崩溃。发行候选必须完成故障注入和持续使用验收：无未处理的已知可恢复错误；保存成功的数据重启后可恢复；渲染／整理失败可重试且不破坏原始内容。意外终止需限制未保存损失，并能在下次启动恢复一致状态。

## 实现建议与待验证参数

工程建议：自动整理默认仅包含收藏／手动纳入的内容，失败批次不覆盖原笔记；隐藏资源预算、队列并发、缓存上限和图谱节点上限均经测试调整。完整体验决定最终语言与渲染方案，不以空窗口基准代替产品资源验收。
