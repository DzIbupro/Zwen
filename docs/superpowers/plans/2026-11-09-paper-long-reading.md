# 长论文按需读取实施计划

沿用已批准的文件适配设计；用户在优先推进长论文自动读取的建议后要求继续。使用writing-plans和executing-plans执行，留在feat/paper-analysis-v2，不调用真实模型、不合并主分支。

选择：短文保持单次Markdown；正文和要求合计超过现有请求材料预算时，提供仅绑定当前论文的read_paper_page/search_paper工具，由兼容Function Calling决定取用正文。不采用固定分批摘要或重新要求报告JSON，也不引入完整agent运行时。参考OpenCode有界offset/limit读取及百炼Function Calling协议，不复制其代码。

- [x] 核心文档工具：当前保存页范围内读页/字偏移与字数、ASCII大小写不敏感字面搜索；单次最多8000字、搜索8条短摘录；错误可返回模型修正。程序记录全文/部分读取与仅搜索命中，预算不足未交付不能算已读。正文指令不授权额外操作。
- [x] 新增标准流式tool_calls解码，支持参数分片；保持普通聊天解码不变。复用现有HTTP、SSE、凭据、取消与响应大小保护。畸形工具协议不能作为正文报告通过。
- [x] 自动长文循环：最多6次HTTP请求（最后一次禁止继续调用工具）、累计工具正文≤96KiB、最终请求JSON≤256KiB、总时限5分钟，不自动重试。每轮重建当前论文工具；不开放路径、shell、网络或无关文件。不默默截断资料/工具结果。保存读取轨迹及程序生成的覆盖说明；没有实际正文读取不得标分析完成。
- [x] 原生worker与绑定接线：直接材料或长文工具请求二选一；固定配置、历史与来源保护保持；预留长文工具上下文，超出预算时明确说明。文字超限不再要求先手动选页，页图8页限制本轮保持。
- [x] 对话卡片发送前说明长文可能多次请求和仅按需覆盖；本机合成工具调用闭环、失败/取消/格式分片回归、独立复核、普通构建同步原桌面与试用入口，更新验收与交接。

非目标：原生PDF模型协议、本地OCR、真实服务能力/内容质量验证。用户已验证上一轮真实桌面拖放及系统阅读器显示正常。

复核决定：按组装后的材料/要求预算选择模式，以免正文刚低于上限但加上skill后仍无法发送。补强：实际读页后，后续模型文字逐段保存，停止/断线不丢已收到回答；所有终止路径写覆盖统计，预留8KiB保存空间。工具阶段的模型文字明确标记可能继续取材，不当成已完成报告。

验收：Rust254/2忽略、前端215、Svelte0/0；60页442380字节PDF的自动工具读取、原文追问、停止闭环通过；短文/页图/拖放原生回归通过。真实服务未调用。安装与最终边界见docs/validation/2026-11-09-paper-long-reading.md。
