# 轻量级研究助手：本机验证后的开发方案

日期：2026-10-29。此文件为原调研方案的修订版；原文件保留。当前选择由助手依据实测提出，供用户审阅。验证脚本均为临时技术原型，不是正式产品。

## 1. 决策

采用 Python＋PyGObject＋GTK4＋SQLite，本机原生运行。优先做选区／截图进入草稿、流式问答、历史与来源保存，然后做收藏和搜索。自动划词浮条、概念图后置。

截图默认选择 **Niri 原生截图命令＋截图完成事件＋唯一输出路径**，当前 GNOME Screenshot Portal 不作为默认后端。GTK Cairo 渲染器作为轻量模式的首选试验配置，仅设置在本应用进程，保留默认渲染器切换；正式默认值由图片、长会话、刷新性能验收决定。

不要求用户为了这个工具更换桌面、安装完整 GNOME 或常驻本地大模型。

## 2. 本机证据与边界

环境：Fedora 45 Server、Niri 26.04、GTK 4.24.1、PyGObject 3.58.1、wl-clipboard 2.3.0；物理内存约 15.2 GiB。两块显示器，2560×1600／150% 与 2560×1440／100%。这只是已检测的显示配置，不表示多屏操作全部验收通过。

| 项目 | 结果 | 含义 |
|---|---|---|
| Screenshot Portal | 实际版本 2，AvailableTargets=0；交互请求约 5ms 返回 response=2 | 不支持用 v3 target=4 强制区域；response=2 是失败而非用户取消 |
| Portal 故障根因 | 用户服务日志：Unknown method 'InteractiveScreenshot' | 与当前 GNOME 后端／Niri 方法缺失相符，不是应用忘记等待 |
| Niri 原生区域保存 | 用户拖选并保存；生成独立 PNG，1280×720、123517 字节 | 不必通过读取剪贴板取回截图 |
| Niri 完成事件 | 实际收到 ScreenshotCaptured，包含相同绝对路径 | 可以按请求路径关联完成事件 |
| Niri 命令返回 | 发起后约 62–69ms 返回 0，图片稍后才生成 | 返回 0 不能当作截图成功 |
| PRIMARY | GTK 测试窗口自动选中中英文，wl-paste 完整读回 52 字节 | GTK4→Niri→wl-clipboard 路径通过；不代表所有应用通过 |
| Niri Esc 取消 | 用户确认按 Esc；独立路径在60秒观察期及最终复查均无文件，旧截图保持独立 | 人工取消行为通过；自动识别取消仍待实现 |
| Gio 单实例 | 两次调用由同一 PID 处理，第二次 remote=True，返回 0 | 可用 Gio 转交命令 |
| GTK4 layer shell | typelib 缺失 | 后续浮条需要额外依赖；不妨碍主窗口 |
| libsoup 3／libadwaita | typelib 可用 | 可选用 GLib 原生异步网络栈 |
| GtkSourceView 5 | typelib 缺失 | MVP 先用等宽文本代码块 |
| SQLite 中文搜索 | 默认 FTS5 搜索“助手”不能匹配“研究助手” | 必须显式设计中文子串搜索 |

GL 轮次中 PRIMARY 测试失败（exit=1）；当时和截图交互重叠，未能隔离焦点因素，所以既不判为 GL 故障，也不隐去这次失败。默认与 Cairo 轮次成功，仍须跨应用验收。

### 内存测量

读取测试进程 `/proc/self/smaps_rollup`。仅包含该进程 CPU 地址空间的 PSS/RSS，不包括完整 GPU 显存及桌面服务增量。单次运行，不是统计基准。

| 渲染器 | 文本窗口 PSS | 隐藏稳定后 PSS |
|---|---:|---:|
| 默认（运行日志出现 Vulkan） | 137.0 MiB | 137.0 MiB |
| GL | 129.1 MiB | 129.2 MiB |
| Cairo | 46.1 MiB | 40.9 MiB |

补充图片原型：Cairo 加载本次截图并以100ms间隔追加50段文本，图片加载时PSS约44.8MiB，移除图片并隐藏后稳定约45.2MiB；解码与程序循环正常完成。没有进行帧率或用户视觉体验评测，不能把这等同于流畅性验收。

文本原型没有真实模型、完整历史、Markdown、公式和数据库加载；不能将这个数字承诺为正式产品内存。默认渲染器出现过 swapchain out-of-date 警告，但程序正常完成；不据此断言桌面有故障。

### 尚未通过的验收

Firefox／Writer／实际 Markdown 编辑器／PDF 阅读器的 PRIMARY、中文输入法组合态、拖选后焦点恢复、跨屏截图、连续截图竞态、磁盘写入失败、30 分钟稳定性、真实模型连接、复杂 Markdown 与公式均未完成。没有安装或运行 Nexora 等第三方项目，不能提供它们的实测比较。

## 3. 为什么选择自建小工具

- 直接使用 Nexora：可能最省日用开发量，但尚未验证本机截图草稿行为、内存与知识整理，不能声称不满足需求。
- 基于完整现有项目修改：可复用界面，但会继承语音／会议等非必要依赖与结构，暂不选择。
- 独立小工具：本轮已验证核心 GTK、选区、单实例和 Niri 截图路径；最便于控制范围与数据结构。推荐此路，但依据是范围匹配，不是已证明比所有现有工具更快或更省内存。

## 4. 首版用户流程

### 文本

Niri 快捷键→在改变焦点前读取 PRIMARY（3 秒超时、文本 MIME、大小限制）→生成不可变摘录快照→显示草稿→用户选择解释／翻译或输入问题→发送。

选区为空或不可读时提示“请复制后使用剪贴板入口”。不能静默使用旧剪贴板。PRIMARY 的内容可能陈旧，预览可编辑，未知来源不自动补全。复制入口是独立命令。

### 图片

1. 记录来源窗口信息作为提示，不当作可靠文献来源。
2. 持久化草稿，隐藏助手。
3. 先连接 Niri event-stream，再生成 UUID 路径并发起 screenshot --path。
4. 同时只允许一个截图请求。仅接受当前路径的 ScreenshotCaptured，忽略其他截图事件。
5. 验证文件可读、格式、尺寸、解码成功，再放入附件目录并显示缩略图。
6. 用户补充问题后发送，截图本身不触发网络请求。

Niri 仍可能自动写系统剪贴板；应用不依赖剪贴板读回，不擅自清空或覆盖用户后续复制的内容。若未来要求“绝不改剪贴板”，必须另选并实测后端，不能承诺当前方案满足。

完成事件只有成功证据时才附加。没有观察到文件不能直接判为“用户取消”；取消／超时状态须明确区分。未得到取消通知时保留草稿并允许手动返回；用户取消或本地超时后将请求标记失效，晚到图片不自动附加。超时不代表关闭了 Niri 截图界面。

## 5. 架构与存储

- **UI**：Gtk.Application＋普通窗口；Cairo 轻量模式；TextView 基础段落、等宽代码、图片预览。公式与 Markdown 先做小样再扩展，不自行重写完整排版系统。
- **生命周期**：Gio.Application 单实例，GUI 只在主实例初始化；隐藏可 hold，明确退出时 release/quit。MVP 不依赖托盘。
- **网络**：优先 libsoup 3 异步 API＋GLib 主循环；流读取不可阻塞 UI；SSE 按协议分帧，处理跨网络块 UTF-8；UI 每 50–100ms 合并刷新。以一个明确支持文本和图片的远程服务起步，不自动扫描用户密钥。
- **并发**：GTK 操作留在主线程；文件、图片缩放、数据库工作放任务队列。SQLite 连接归一个工作线程所有，避免跨线程共享连接。
- **取消与重试**：请求有独立 ID；停止后忽略迟到片段；部分回答保留，重试生成新的回答记录，不拼接重复文本。
- **数据**：conversations、messages、drafts、attachments、sources、notes、tags、note_tags；后期再加 concepts、relations、relation_evidence。附件有 draft_id 或 message_id 的明确归属与约束。
- **一致性**：先写临时文件、验证并原子改名，再提交数据库引用；启动时清理超过保留期的孤立临时文件。删除、取消、崩溃恢复均保留明确状态。
- **来源**：标题／URL 或文件 URI／页码／摘录。未知允许空；截图不自动捏造页码。
- **中文搜索**：首版小数据集使用参数化子串匹配（如 instr），覆盖一到两个汉字；数据变大后再引入分词索引。FTS5 用于适合的全文词项，不能默认等于中文检索。
- **密钥与日志**：配置地址与模型；Secret Service 按需使用，缺失时明确配置环境变量。日志不记正文、图片与密钥。
- **模块**：app、ui、selection、capture/niri、providers、storage、notes。Portal 保留接口位置，不为当前失败的后端做虚假回退。

## 6. 开发顺序与验收门槛

### A：巩固本机输入链路

完成 Firefox 与一个实际阅读器的选区测试；截图自动取消识别、连续两次请求、晚到事件、丢失事件恢复、多屏与150%缩放；中文输入法；Cairo 图片与文本刷新性能。快捷键安装前检查主配置和 include 文件，禁止覆盖现有 Mod+Shift+E（退出 Niri）。

### B：最小可用聊天

一个 Provider，流式文本／图片、多轮、停止、断网、鉴权失败、限流、草稿恢复、历史分页。完成“阅读→摘录／截图→提问→追问→保存”闭环。暂不做自动摘要，先明确上下文截断并允许查看发送范围。

### C：研究整理

收藏、标签、中文搜索、来源回溯、Markdown 导出。保留原始问答与附件引用。真实使用一周后再判断整理功能缺口。

### D：可选自动浮条

先固定位置、不开全局鼠标钩子；PRIMARY 监听、防抖、去重、明确启停；只有点击动作才发往模型。不承诺在每个应用光标旁定位。

### E：概念图

人工关联起步；AI 只建议关系，用户确认；边附证据；一跳邻域限制节点数量。不引入 Neo4j、常驻向量服务或 GraphRAG。

不沿用原方案按天估算。按验收推进，先完成 A、B；复杂排版和桌面兼容性是主要不确定性。

## 7. 性能验收

Cairo 模式隐藏 PSS≤100MiB、普通聊天≤180MiB 继续作为优化目标，不作为当前保证。每轮记录进程树、渲染器、图像像素、历史量、PSS/RSS、CPU 和 GPU 统计可见范围。测量冷启动、窗口隐藏、20 张不同截图、删除图片、30 分钟使用后的稳定值与峰值。

如果超预算，先看渲染器、图片缓存、历史数量，再考虑实现语言。只有在可见性能和能耗表现符合要求时才正式选 Cairo；不能仅凭 PSS 低判它全面更好。
