# 开发方案 v2：资源与稳定性优先

更新：2026-10-29。依据：[需求基线](requirements.md)。本方案替代最初锁定Python／原生纯文本和人工确认每条知识关系的设计；[历史本机验证](validation/2026-10-29-fedora-niri.md)仍有效，但仅是原型证据。

## 1. 技术选择状态

**最终语言、窗口与回答渲染框架暂不锁定。**现有Python包保留为基线，不宣称已选定正式实现。先完成[选型验证计划](decisions/technology-evaluation.md)，再为选中的架构编写业务实施计划。

候选以三个组合为限：

| 组合 | 要验证的收益 | 代价／未知 |
|---|---|---|
| Python＋GTK4＋按需回答渲染组件 | 已验证的输入链路、快速迭代与较低基线 | 现有40–137MiB数据没有表格／公式渲染；嵌入WebView后须重测 |
| Rust＋GTK4＋同等回答渲染组件 | 强类型状态约束、编译交付、原生系统集成 | 编译／依赖与异步集成复杂度；没有本机资源或稳定性对照数据 |
| Rust＋系统WebView界面（如Tauri） | 精致面板、Markdown／公式和可视化复用网页生态 | WebView子进程与内存、Niri焦点、隐藏后资源回收均待测 |

Go与Java不作不成熟判断；只有候选不满足要求，或发现明确的平台优势，才扩展对照，避免无限试栈。Rust不是预定胜者，用户Python基础也不是加权项。候选框架／依赖版本以实际验证时的官方资料和锁文件为准。

## 2. 系统划分

逻辑上划分桌面入口、会话与草稿、模型请求、内容展示、笔记库、知识整理、图谱视图。不据此预先拆成多个常驻服务。

- 桌面入口：单实例、show／ask-selection／ask-clipboard／capture／quit；无参数等同show。show不采集上下文。
- 输入：改变焦点前取得显式选区快照；读取限时限量，失败不读旧剪贴板。截图先订阅Niri事件，再使用UUID绝对路径发请求；同时仅一个截图请求。Niri的Esc不保证有取消事件；pending有超时或手动返回草稿的出口，超时标记expired，不冒称用户取消；失效后迟到事件不得附加。
- 草稿与会话：先持久化材料和草稿；流式响应带独立generation ID；停止、失败、重试均明确记录，迟到片段不能污染新回答。
- 模型：一个用户配置的文本／图片Provider起步；联网异步，有超时与取消；SSE处理跨块UTF-8和完整事件边界；不在部分回答后自动重试并拼接。
- 回答展示：首版完整覆盖需求中的常用Markdown、表格和公式；不能以TextView平文本作为最终验收。比较原生组件组合与按需WebView，不先承诺其内存。
- 笔记：MD正文、相对附件链接、稳定ID；SQLite保存聊天、草稿、整理任务、关系与索引，搜索索引可以从正文重建。
- 整理：已授权范围内自动增量处理，默认一条整理任务并发；不在UI主线程运行或调用模型。
- 图谱：本地关系查询＋局部视图；视图按需创建，隐藏／关闭可停止布局与动画。

## 3. 数据与一致性

建议表：conversations、messages、drafts、attachments、notes_index、sources、topics、concepts、topic_memberships、relations、relation_evidence、organize_jobs、organize_revisions、manual_overrides。关系有来源ID、说明、模型／版本、证据及推断标记。

MD正文是笔记正文的权威；每篇笔记用稳定ID，标题变化不改变身份。附件引用使用可迁移的相对路径。人工修改、外部编辑与AI整理均以正文哈希／修订号做并发检查，不以AI结果覆盖更新后的正文。

文件系统与SQLite不能假装有跨介质原子事务：采用临时写入→验证→原子改名→数据库事务＋可恢复作业日志。崩溃恢复检测未完成作业、孤立文件和损坏引用；不能见到孤立文件就立即删除用户内容。迁移前备份，迁移失败保留旧版本。

原始材料与AI整理产物分开。模型返回结构化结果后先校验：ID存在、主题／边格式正确、无悬空证据、预算内，再事务提交一批关系。记录变更集，实现撤销；AI批次不能覆盖人工锁定分类。默认不自动删除／合并原始MD笔记；合并栏目不等于删除证据。笔记编辑后，依赖旧修订的AI分类／关系标记待重算或失效；删除材料时断开证据链接并记录变更，不保留可点击的悬空引用。增量整理只重算受影响材料，保护人工关系与撤销记录。

中文子串搜索首版使用参数化匹配，数据增大后实测分词／索引；默认FTS5不代表中文子串可用。

## 4. 渲染与前端约束

Vida为桌面面板交互参考；品牌与资产不照搬。正式UI须先给用户看可交互视觉样例，确定唤出、收起、输入、材料预览、回答、历史和知识视图的关系，不能拿官网营销页作为桌面面板已复刻的证据。

如使用WebView：Markdown关闭原始HTML或严格净化；不加载回答中的任意远程脚本；公式与图谱依赖本地打包；外部链接交给系统浏览器。界面脚本仅可调用最小权限桥接接口，回答内容不能执行本机命令。限制图片解码像素、文本长度和图谱节点数量。

格式错误的公式显示明确的局部错误或可复制源文，不导致整条回答／进程崩溃。流式输出按50–100ms批量刷新，未闭合的代码／公式不每个token重建整个页面。是否能保留高亮、滚动位置和用户选择由样例验收。

## 5. 资源策略与稳定性

默认远程推理，不常驻OCR／向量模型。先使用按需查询和增量整理；需要向量检索时再以真实搜索缺口论证。历史分页、缩略图有界缓存、图谱默认局部、隐藏时停动画与布局。

WebView回收要先保存草稿；不得销毁唯一的会话状态。渲染进程退出时，原始会话与任务仍可恢复，提供重建视图动作；原生GTK崩溃也有数据持久化恢复路径。是否需要轻量常驻入口与可退出UI进程，由完整进程树测量决定，不默认增加守护进程掩盖崩溃。

网络故障、HTTP429／401、响应格式错误、截图取消／迟到、文件不可读、磁盘满、数据库锁、非法模型关系均作为可恢复状态；不能捕获异常后静默丢数据。停止请求可在UI立即生效，底层取消有边界，后台迟到结果失效。

日志默认仅状态、耗时、错误类型；不记正文、图片、密钥。密钥优先Secret Service或用户显式环境配置。Linux资源耗尽导致进程被杀无法完全避免，采用大小限制、并发上限、周期持久化及下次启动恢复降低后果。

## 6. 阶段与交付

0. **选型**：相同功能样例、完整进程树资源、失效恢复对照；产出技术决策记录及Vida式交互样例，确定语言／框架。
1. **问答助手**：单实例、输入材料、表格公式、一个Provider、流式、多轮、停止、草稿和历史恢复；首版必须有正常格式展示。
2. **知识库**：MD保存、搜索、来源、附件、人工修改与导出；明确哪些内容参与整理。
3. **AI自动整理**：主题／栏目、多归属、关联、增量任务、证据、撤销、人工修正保护。结构化结果先离线故障测试，再接真实模型。
4. **可视化网络**：节点、关系、搜索筛选、展开、定位笔记和证据；大库性能与UI恢复验收。
5. **自动划词浮条**：在实际应用矩阵验证，保留可关闭模式；不采集当前应用整体上下文。

自动浮条也可在输入链路稳定后提前，但不拖延正常聊天与知识库。旧[Python基础实施计划](superpowers/plans/2026-10-29-foundation.md)标记为被取代，不能在技术门槛之前继续按它扩写业务。

## 7. 验收预算与证据

以下为工程试验预算，不是实测承诺：隐藏稳定后应用进程树PSS争取≤100MiB；普通聊天含表格公式争取≤180MiB。达不到时报告实际值与功能取舍，不能删掉必需的表格／公式来伪造达标。内存、CPU、GPU可见统计分别报告。

首字网络延迟与本地唤出分开测；热唤出目标300ms，持久化输入后故障恢复损失不超过最后一次成功保存；草稿防抖保存目标≤1秒，发送前显式提交。空闲CPU取60秒窗口、与空桌面基线比较；目标≤单逻辑核心1%，并报告后台整理是否正在运行。

发行候选：3次重复资源测试；100次唤出／隐藏和连续输入；至少30分钟综合初测，再8小时持续使用／空闲混合测试。要求无意外退出、无已保存数据丢失、无未解释的持续线性内存增长；20张不同截图、20条长回答、图谱局部视图、整理中取消与重启均纳入场景。

30分钟无崩溃不能宣称长期稳定，也不等于Rust已证明比Python可靠；单元、集成、故障注入和真机验收一起支持结论。
