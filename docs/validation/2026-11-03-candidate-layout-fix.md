# 划词候选布局修补（2026-11-03）

用户真实截图证明：候选弹出时残留旧回答，且“查看待处理选区”“其他”文字竖排、重叠。

根因：Capsule无候选专用呈现状态，直接渲染ChatController中上一条回答；app.css的summary全局规则将所有summary限制为30×30，原本仅用于标题栏更多操作。

修补：候选状态只显示标题和选区操作，不显示旧回答、输入框、截图、演示按钮及旧文档提示；原聊天记录不删除。问一问添加成功后准备独立新会话（未保存旧回答时阻止），避免进入草稿时再显示旧结果。全局summary尺寸仅作用于标题栏，选区组件明确横向尺寸、不折字和按钮不收缩；加深文字/按钮对比度。

验证：新增带旧回答的胶囊组件测试先失败（旧data-capsule-answer存在），修补后通过；全部112项前端测试通过，Svelte0错误/0警告，Vite构建通过。真实浏览器加载同一Capsule和app.css合成场景，展开其他动作，确认oldAnswer=false、composer=false，选项nowrap、按钮高度约26px，无竖排或重叠。截图：artifacts/validation/candidate-menu-fixed.png。仅合成选区和旧回答，不调用AI、不读取用户材料。

CUA原生窗口能力不可用，浏览器共享前端布局证据不等同于Fedora所有缩放/跨应用真人鼠标验收。普通程序构建与哈希在收尾记录中更新。
