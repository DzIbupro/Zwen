# 截图视觉模型接入验证 · 2026-10-31

环境：Fedora 45，Niri 26.04，Rust 1.98.1。合成验证全部使用回环 HTTP 服务与合成 PNG；**没有连接真实智谱服务，没有读取或上传真实截图材料。**

## 1. 官方协议核对

依据官方模型页 [GLM-4.6V-Flash](https://docs.bigmodel.cn/cn/guide/models/free/glm-4.6v-flash)：

- 请求为 OpenAI 风格 `content` 数组：`{"type":"image_url","image_url":{"url":...}}` 与 `{"type":"text","text":...}`；
- 该模型页的官方示例直接使用**裸 base64 字符串**（不要求 `data:` 前缀），本实现采用裸 base64；
- 支持一条消息多张图片；支持 `"stream": true` 流式；模型名 `glm-4.6v-flash`；
- 该页未给出图片大小/分辨率数值。旧版 GLM-4V 公开规范为 ≤5MB、≤6000×6000、png/jpg（[社区转述](https://cloud.tencent.com/developer/news/2017439)），本实现取更保守值：**单张请求负载 ≤4MiB、边长 ≤6000**。这两个数值尚未经真实服务确认。

## 2. 本单元实现边界

- 模型设置新增可选"图片模型"（`imageModel`）。留空时序列化配置与旧格式逐字节一致，旧对话绑定不受影响；填写后 profile 变化，旧对话按既有机制要求新建对话（不把旧上下文转发到不同配置）。
- 发送时若草稿带截图：路由到图片模型；未配置图片模型则拒绝（前端禁用发送，后端 `image_model_missing` 双重拦截），绝不把图片发给文字模型，也不把文件名冒充图片。
- 图片负载：从本机附件原样有界转换（≤4MiB、≤6000px，必要时等比缩小；最小 256px，仍超限则拒绝），裸 base64 放入 `image_url.url`；本机原图不修改、不上传原始文件本身之外的数据。文字部分仍受 256KiB 预算约束，图片不计入。
- transport 层独立校验：全请求图片数 ≤8、单张 base64 ≤8MiB 且必须是合法 base64 字符集，非法负载在任何网络请求前拒绝。
- 会话与历史：图片轮的 `turn.model` 记录图片模型；追问在同一会话内以纯文本进行（历史上下文不回带图片，需图片时重新截图附加）。发送接受后附件即被消费移除（与草稿同语义）；后续流式失败不回收附件，重试保存只保存文字回答。此边界已写入文档与验证。
- 密钥路径不变：仍由 `ZWEN_API_KEY` 环境提供，图片模型与文字模型共用；不写 SQLite/日志/IPC。
