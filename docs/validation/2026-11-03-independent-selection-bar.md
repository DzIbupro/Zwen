# 独立划词操作条接入（2026-11-03）

## 当前实现

PRIMARY自动候选不再激活主窗口，也不再修改主窗口激活意图。选区事件到来时先记录近似位置，再等待文字稳定；后续显示只消费先前锚点，不重新采样移动后的鼠标。有效候选在同进程GTK3/layer-shell操作条呈现：问一问Zwen、翻译、详细解释、其他、自定义动作及设置入口。操作条keyboard mode NONE、exclusive zone0；按钮在点击后才冻结选区ID并激活胶囊，设置入口激活主设置。近似锚点来自一次短命透明指针进入探针，不是精确词句边界。探针最长200ms，首次进入时立即清空输入区域、销毁，再建立操作条；无位置不退回居中胶囊。

提示词配置revision随显式命令校验，更新冲突会刷新配置并给出重试提示。命令去重有界；页面重载/普通候选刷新不自动重发。旧草稿、截图、未保存回答仍受保护。请求继续走独立纯文本入口，不混入旧会话/截图。

## 生命周期与审查

- 开关关闭会使待呈现的异步结果失效；迟到配置读取不能重弹。
- 来源同时记录Niri进程PID和window ID；读取前后、呈现、点击前核对来源，避免同进程不同窗口误用。
- 新选区可替换未冻结候选，旧读取无效；清空选区、切换来源、监听关闭、监视器变化会关闭操作条。
- GTK对象只在主线程使用；销毁/信号断开时不持有RefCell借用；探针只接受第一个进入事件，取消使用原子代际校验。
- 主窗口显式激活/截图入口会撤销操作条；无操作来源监测有20秒上限。

独立审查发现的3个P2（关闭后重弹、同PID换窗、提示词冲突静默）已修补；复审无新P1/P2。未修改系统辅助功能开关，未使用原始输入权限或截图OCR。

## 真实输入检查（已完成限定场景）

scripts/validate_bar_input.py创建合成GTK文字/点击计数器，用文件模拟PRIMARY、不读取系统实际选中文字。用户按提示拖选、快速点击和按住后松开；脚本记录drag/check/press计数和操作条出现次数。用于检查一次性透明定位层是否干扰点击，以及位置是否跟随文字附近。第一次实测发现定位偏远：文字在顶部，但等待200ms后才采鼠标，用户已移到下方检查按钮。改为文字去抖前先记录锚点，禁止迟到重新取位置；另修复旧会话清理误撤销新锚点/旧读取覆盖新预留的竞争。首次计数5个选择结束/4次按下/4次点击，不据此单独判定吞点击；计数器随后改为只有真正移动拖动才计数。复验得到3次拖选、3次按下、3次点击、3次操作条；用户明确反馈“定位准确，并且没有任何的错误”。这验证的是本机合成GTK场景，包括快速移向下方按钮与按住1秒后松开，不代表所有输入时序绝无影响。

多屏、分数缩放、各来源应用PRIMARY兼容性仍需后续覆盖；不能把单机/合成链路宣称全部页面支持或精确词句边界定位。
