# 长论文自动按需读取

用户在优先实现长论文读取的建议后授权继续。分支仍为feat/paper-analysis-v2，未合并main。用户已确认前一轮真实桌面的PDF拖放与系统阅读器显示正常。

## 行为与实现

正文和阅读要求合计能放入现有单次材料预算时，保持全文→skill→Markdown单请求。超限时不再在新建检查阶段要求先选页，改用本篇限定的标准Function Calling。最后仍为自由Markdown，不恢复报告JSON或固定分批证据流水线。

- read_paper_page：仅本次保存页范围内，Unicode字符offset/limit，每次最多8000字，明确剩余字数与下一偏移。
- search_paper：当前范围字面搜索，ASCII字母不分大小写，最多8页短摘录，不开放正则、路径、shell、网络或无关文件。
- 页索引每页仅12字预览。程序区分完整返回文字、部分返回、未读、无文字页与搜索短摘录；预览/搜索不算整页已读。覆盖说明明确不代表全文精读，图表未由此读取。
- 每轮最多6次HTTP请求，最后一轮禁止工具；累计编码工具文字96KiB，请求JSON≤256KiB，整轮最长5分钟，不自动重试。这些是应用保护预算，不宣称已核实服务的实际token容量。
- 每次追问重新绑定相同私有来源与保存范围，继续固定启动时配置。长文为工具上下文保留空间，携带的近期问答JSON≤24KiB，contextTurns反映实际携带数量。无工具正文读取不得标分析完成。
- 实际取材后，后续模型文字逐段写入现有聊天生命周期；标明可能继续取材。停止、断线、格式错误同样保存已收到内容及程序覆盖统计，预留8KiB供终止记录。输出达到保护限额会显示失败并保留已接收内容。
- 前端发送说明包含长文可能多请求和按需覆盖，可用既有停止按钮。无新页面、无数据库迁移，也不向模型暴露宿主文件路径。

参考[OpenCode有界读取工具](https://opencode.ai/docs/tools/)及[百炼Function Calling协议](https://help.aliyun.com/zh/model-studio/qwen-function-calling)。复用Zwen现有HTTP、SSE、凭据归属、取消、持久化和渲染；未引入完整agent运行时或复制第三方实现。

- 前端215通过，Svelte0错误/0警告，Vite通过（既有大chunk提示）。

- 独立复核发现最终文字缓冲导致停止/断线丢输出，以及失败时缺覆盖统计，两项均已修复并有回归。端到端测试还抓到新建入口残留旧大小检查，已接入新prepare路径并复测成功。测试自身的控件等待与停止分片时序已修正，不冒充产品修复。
