# 双模式/胶囊验证 · 2026-10-29

状态：按用户确认的“大窗口完整问答、小胶囊快捷阅读”调整需求v3与设计v4，并实现第一版原生胶囊。模型与选区/截图集成仍未实现，演示回复明确不是AI结果。

## 实现

- 无参数/show：完整窗口；capsule：小浮窗；界面按钮可互相切换。
- 同一WebView、草稿控制器和父级回复缓冲；切换不复制/重置草稿，不重启生成。
- 默认480×96逻辑像素，固定宽度、顶部居中，回复向下增长；上限为本次打开所用屏幕高度约55%，到上限后回答区滚动。
- 原生约束与前端都钳制尺寸。ResizeObserver按节流发送，原生请求串行合并到最新高度，generation拒绝旧请求。CSS像素通过devicePixelRatio/原生scaleFactor换算，处理缩放变化通知。
- Niri适配器只按本应用PID查找唯一窗口，对此ID执行浮动/定位；不保存其他应用的标题或作为上下文，不修改配置文件。其他桌面环境只做窗口API尽力定位。
- 演示支持停止，部分文本保留；从胶囊展开到完整窗口后继续显示同一回复。演示不持久化，草稿仍使用原有SQLite保存。

## 真正桌面测试

`scripts/validate_capsule.py`使用专用smoke构建、独立临时数据库，只操作自己启动的窗口。最后一次本机Niri采样：

| 阶段 | 原生窗口尺寸 | 浮动 | 顶部位置（工作区视图） |
|---|---|---|---|
| 初始 | 480×约96（采样97，含舍入） | 是 | x1040,y89 |
| 回复增长中 | 480×290 | 是 | x1040,y89 |
| 达到上限 | 480×792 | 是 | x1040,y89 |
| 再次唤出 | 回复恢复到同一上限 | 是 | 原生/DOM高度检查通过 |
| 转入完整窗口 | 1268×1383 | 否 | Niri平铺 |

当前输出逻辑尺寸2560×1440；792=1440×55%。坐标包含Niri工作区顶栏预留，应用请求的顶部偏移是48。DPR约1.05，不能直接把CSS像素当作Niri逻辑尺寸。

脚本验证回答实际可滚动、输入不被撑出、展开后草稿及已收文本保留、旧尺寸消息不缩小完整窗口；重复唤出回归通过，退出0。原有三个桌面关闭/重载/重启/第二实例quit测试也通过。

早期实测复现了Linux resizable=false触发约200像素最小高度的问题；采用相同min/max尺寸约束锁定窗口，保留resizable=true后实际紧凑尺寸通过。上游记录：[tao#561](https://github.com/tauri-apps/tao/issues/561)。未为此重新安装GTK4或替换技术栈。

原始记录在本机artifacts/validation/capsule.json；浏览器界面截图为artifacts/capsule-compact.png、capsule-expanded.png。浏览器截图只说明样式，原生窗口尺寸以上述Niri证据为准。
